## JPA란

JPA는 자바 진영에서의 ORM이다. CRUD SQL을 직접 작성할 필요가 없고, 조회된 결과를 객체로 매핑하는 작업도 자동으로 처리해준다.
SQL이 아니라 객체 중심으로 개발하게 되면서 버그가 많이 줄었다.

## 기본 동작

| 작업 | 방법 |
| --- | --- |
| 저장 | `jpa.persist(member)` |
| 조회 | `jpa.find(Member.class, id)` |
| 수정 | 조회한 객체의 세터 호출 (`member.setName(...)`) |
| 연관된 객체 조회 | 게터 호출 (`member.getTeam()`) |

수정할 때 별도의 update 메서드를 부르지 않고 세터만 호출해도 반영되는 게 인상적이다.
조회한 객체는 영속성 컨텍스트가 관리하고 있어서, 값이 바뀌면 트랜잭션이 끝날 때 UPDATE 쿼리가 자동으로 나간다.

## 왜 ORM이 필요한가

ORM 없이 JDBC로 개발하면 이런 문제가 생긴다.

- **SQL에 의존하게 된다.** 필드 하나가 추가되면 그 객체를 쓰는 INSERT, UPDATE, SELECT를 전부 찾아 고쳐야 한다. 하나라도 빠뜨리면 그때부터 버그다.
- **CRUD 코드가 반복된다.** 테이블이 늘어날 때마다 똑같이 생긴 SQL과 매핑 코드를 다시 쓴다.
- **객체답게 설계할 수 없다.** 객체 모델을 제대로 만들수록 SQL로 저장하기 어려워져서, 결국 테이블에 맞춰 객체를 납작하게 만들게 된다.
- **진짜 객체인지 알 수 없다.** `member.getTeam()`이 되는지 안 되는지가 그 member를 조회한 SQL이 팀을 조인했는지에 달려 있다. 객체를 믿고 쓸 수 없다.

결국 문제의 뿌리는 객체와 테이블이 서로 다른 방식으로 데이터를 다룬다는 것이다.

## 객체와 테이블의 패러다임 불일치

객체는 속성(필드) + 기능(메서드)로 이루어진다. 문제는 이걸 그대로 테이블에 저장할 수 없다는 것이다.

- **상속**: 부모 객체를 상속한 객체는 SQL로 저장하려면 부모 테이블과 자식 테이블에 나눠 넣어야 한다. JPA는 이 상속 구조 매핑을 알아서 처리해준다.
- **연관관계**: 객체는 참조로 연관된 객체를 조회한다(`member.getTeam()`). 테이블은 FK를 사용해 조인으로 연관된 테이블을 조회한다. 방향도 다르다 — 참조는 단방향이지만 조인은 양쪽 어디서든 가능하다.

## 지연 로딩 (lazy loading)

연관된 객체를 미리 다 조회해두면 안 쓰는 데이터까지 가져오게 된다.
JPA는 실제 객체를 사용하는 시점까지 DB 조회를 미룬다. 이걸 지연 로딩이라고 한다.

```java
Member member = jpa.find(Member.class, id);  // SELECT * FROM member
Team team = member.getTeam();                // 아직 쿼리 안 나감
team.getName();                              // 이 시점에 SELECT * FROM team
```

## 마이바티스는?

마이바티스는 ORM이 아니라 **SQL 매퍼**다. SQL과 매핑할 객체만 지정하면 JDBC API를 다루는 일과 응답 결과를 객체로 매핑하는 일은 마이바티스가 처리해준다.
SQL은 여전히 내가 쓴다는 게 JPA와의 차이다.

파이썬에도 같은 게 있는지 찾아봤다.

- **aiosql**, **PugSQL** — `.sql` 파일에 이름 붙여 쿼리를 쓰면 파이썬 함수로 만들어준다. 마이바티스와 가장 비슷하다.
- **SQLAlchemy** — ORM과 Core(쿼리 빌더)를 둘 다 가지고 있다. 객체로 다루고 싶으면 ORM, SQL을 직접 조립하고 싶으면 Core를 쓴다.

자바처럼 "JPA냐 마이바티스냐"로 갈리지 않고, 파이썬은 SQLAlchemy 하나로 양쪽을 다 하는 편이다.


## 책과 현재의 차이

현재 김영한 저 『자바 ORM 표준 JPA 프로그래밍』을 보고 있다. 2015년 책이라 지금과 달라진 부분이 있어서 같이 정리해둔다.

- **패키지 이름**: `javax.persistence` → `jakarta.persistence`. 오라클이 자바 EE를 이클립스 재단에 넘기면서 `javax` 상표를 못 쓰게 돼서 이름이 바뀌었다. 코드는 그대로고 import만 바뀐다.
- **이름**: JPA(Java Persistence API) → Jakarta Persistence. 그래서 요즘 문서에는 "Jakarta Persistence 3.x"로 나온다.
- **구현체**: 책은 하이버네이트 4~5 기준인데, 스프링 부트 3부터는 하이버네이트 6이 기본이다.
- **스프링 부트 3**: 자바 17 이상 + `jakarta` 네임스페이스가 필수다. 책을 따라 하다가 import가 안 잡히면 대부분 이 문제다.
